# End-to-End Submission Workflow

This document describes the full workflow for submitting Scouting NanoAOD production jobs
to the CMS CRAB system from the `Run3_nano_submission` repository.

## High-Level Workflow

The submission pipeline follows five stages:

1. **Setup environment** -- Install CMSSW, ScoutingTranslator, and RecoBTag plugins.
2. **Select datasets** -- Choose which MC samples or data eras to process from JSON catalogs.
3. **Configure CRAB** -- Generate per-dataset CRAB configuration files from the template.
4. **Submit** -- Send jobs to the grid via `crabby.py --submit`.
5. **Monitor** -- Track job progress with `crab_status.py` and handle failures.

```
setup.sh          datasets/*.json       crabby.py --make       crabby.py --submit       crab_status.py
   |                   |                     |                      |                        |
   v                   v                     v                      v                        v
 CMSSW_16_0_1    MC_2024.json         crab/<TAG>/...          CRAB server           CrabStatus.csv
 + ScoutingTranslator  DATA_2024.json    submit_*.py files     grid worker nodes      ProgressPlots/
 + RecoBTag plugins
```

## Prerequisites

Before submitting jobs, ensure the following are available:

### CMSSW Environment

The repository requires **CMSSW_16_0_1** on an `el8_amd64_gcc13` platform. Run `setup.sh`
to create the CMSSW area under `cmssw/CMSSW_16_0_1/`. The script sources
`/cvmfs/cms.cern.ch/cmsset_default.sh`, creates the SCRAM project, symlinks the
`customizations/` directory into `DAZSLE/DAZSLE/python`, and compiles with `scram b -j8`.

After `setup.sh`, install the scouting-specific packages manually:

- **ScoutingTranslator**: Clone from `ArghyaRanjanDas/ScoutingTranslator` into
  `cmssw/CMSSW_16_0_1/src/PhysicsTools/ScoutingTranslator/`.
- **RecoBTag plugins**: Copy `RecoBTag/ONNXRuntime` and `RecoBTag/FeatureTools` from
  Yao Yao's depot at `/depot/cms/private/users/yao317/Analysis/HHtoBBTautau/cmssw/tmp/CMSSW_16_0_1/src/RecoBTag/`.
- **UParT ONNX models**: Copy `model.onnx` files into
  `RecoBTag/Combined/data/UParTAK4/Scouting_HHbbtautau/V00/modelfile/` and
  `RecoBTag/Combined/data/UParTAK4/Scouting/V00/modelfile/`.
- Recompile: `scram b -j8`.

### VOMS Proxy

A valid grid proxy is required for CRAB submission and DAS queries:

```bash
voms-proxy-init --voms cms --valid 168:00
```

### CRAB Client

The environment must be initialized in a specific order. Sourcing `crab-setup.sh`
after `cmsenv` is critical because the CRAB client modifies the Python path:

```bash
cd cmssw/CMSSW_16_0_1/src
source /cvmfs/cms.cern.ch/cmsset_default.sh
cmsenv
source /cvmfs/cms.cern.ch/common/crab-setup.sh
cd /path/to/Run3_nano_submission
```

**Important:** The DAS client (`dbs3-client`) does not work after sourcing `crab-setup.sh`.
If you need to regenerate dataset JSONs, do that in a separate terminal before setting up CRAB.

### Dataset JSON Files

Dataset catalogs live in `datasets/`. They are generated by `datasets/get_mc.py` (MC)
and `datasets/get_datasets.py` (data) using the DBS API. Available JSON files:

| File | Content |
|------|---------|
| `MC_2024.json` | 2024 MC samples (HH4b, HHbbtt, TT, DYJets, QCD, etc.) |
| `DATA_2024.json` | 2024 data (JetMET, Muon, EGamma, Tau, etc.) |
| `MC_2022.json` / `MC_2022EE.json` | 2022 pre-EE / post-EE MC |
| `MC_2023.json` / `MC_2023BPix.json` | 2023 pre-BPix / post-BPix MC |
| `DATA_2022.json` / `DATA_2022EE.json` | 2022 data |
| `DATA_2023.json` / `DATA_2023BPix.json` | 2023 data |
| `Scouting_DATA.json` | Scouting-specific data datasets |

## Quick-Start Guide

### Test a Single Dataset

Run a single-unit test to verify the configuration compiles and the job sandbox is correct:

```bash
python3 crabby.py --year 2024 --dataset HHbbtt --scouting --make --submit --test True
```

This creates one CRAB job processing a single luminosity section, with publication disabled.

### Full Scouting Production

Submit all HH signal and background samples for 2024 scouting NanoAOD:

```bash
python3 crabby.py --year 2024 --dataset HHbbtt --scouting --make --submit
python3 crabby.py --year 2024 --dataset DYJetsNLO --scouting --make --submit
python3 crabby.py --year 2024 --dataset TT --scouting --make --submit
python3 crabby.py --year 2024 --dataset DYJetsLO --scouting --make --submit
```

### Standard (Non-Scouting) Production

Omit the `--scouting` flag to use the standard NanoAOD configuration:

```bash
python3 crabby.py --year 2024 --dataset HH4b --make --submit
```

### Check Status

```bash
python3 crab_status.py --years 2024 --samples HHbbtt TT DYJetsNLO
```

## Common Workflow Patterns

### Two-Phase Submission (Make Then Submit)

Separate `--make` from `--submit` to inspect the generated CRAB configs before submitting:

```bash
# Phase 1: generate configs only
python3 crabby.py --year 2024 --dataset HHbbtt --scouting --make

# Inspect generated files
ls crab/NanoAODv15Scouting24/mcscouting_2024_HHbbtt/

# Phase 2: submit
python3 crabby.py --year 2024 --dataset HHbbtt --scouting --submit
```

### Custom Campaign Tag

Override the default campaign tag with `--campain`:

```bash
python3 crabby.py --year 2024 --dataset TT --scouting --campain MyCustomTag_v1 --make --submit
```

### Using a YAML Card

Supply a YAML card to override default CRAB parameters (storage site, publication, etc.):

```bash
python3 crabby.py --year 2024 --dataset HHbbtt --scouting --card my_config.yaml --make --submit
```

The YAML file should contain a `campaign:` key whose values override the defaults in `crabby.py`.

### Regenerating Dataset JSONs

If new MC samples become available or existing ones are invalidated:

```bash
cd datasets
pip3 install dbs3-client   # if not already installed
python3 get_mc.py --years 2024 --samples HHbbtt TT --overwrite-samples
```

This queries the DBS API and updates `MC_2024.json` in place.
