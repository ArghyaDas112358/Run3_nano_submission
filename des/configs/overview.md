## crabby.py Config Mapping

The `crabby.py` script maps (data type, year) pairs to config files via the
`CONFIGS` dictionary:

```
CONFIGS["data"]["2022"]       -> DATA_2022_NANO.py
CONFIGS["data"]["2022EE"]     -> DATA_2022_NANO.py
CONFIGS["data"]["2023"]       -> DATA_2023_NANO.py
CONFIGS["data"]["2023BPix"]   -> DATA_2023_NANO.py
CONFIGS["data"]["2024"]       -> DATA_2024_NANO.py

CONFIGS["mc"]["2022"]         -> MC_preEE2022_NANO.py
CONFIGS["mc"]["2022EE"]       -> MC_postEE2022_NANO.py
CONFIGS["mc"]["2023"]         -> MC_preBPix2023_NANO.py
CONFIGS["mc"]["2023BPix"]     -> MC_postBPix2023_NANO.py
CONFIGS["mc"]["2024"]         -> MC_2024_NANO.py

CONFIGS["mcscouting"]["2024"] -> MC_2024_Scouting.py
```

Note that `DATA_2022_NANO.py` is reused for both 2022 and 2022EE data, and
`DATA_2023_NANO.py` covers both 2023 and 2023BPix. The scouting path
(`mcscouting`) falls back to standard MC configs for years prior to 2024.

## Common Structure Shared Across Configs

All configs are auto-generated by `cmsDriver.py` (ConfigBuilder) and share this
skeleton:

1. **Process definition** -- `cms.Process('NANO', <Era>)` with an era modifier.
2. **Standard service loads** -- Services, HepPDT, MessageLogger, EventContent,
   MixingModule (MC only), Geometry, MagneticField, FrontierConditions.
3. **NanoAOD module load** -- Either `PhysicsTools.NanoAOD.nano_cff` (standard)
   or `PhysicsTools.NanoAOD.custom_run3scouting_cff` (scouting).
4. **Input source** -- `PoolSource` with a placeholder MiniAOD file. The actual
   input is overridden at CRAB submission time.
5. **Process options** -- Multithreading (4 threads), event setup, file mode.
6. **GlobalTag** -- Year-specific conditions database tag.
7. **Path definitions** -- `nanoAOD_step` (main processing), `endjob_step`,
   output endpoint.
8. **Schedule** -- Ordered list of paths.
9. **Customization chain** -- Ordered sequence of `process = customizeX(process)`
   calls.
10. **Early deletion** -- Memory optimization via `customiseEarlyDelete`.

## How Configs Differ

### By Data Type

| Aspect | MC Configs | Data Configs | Scouting Config |
|---|---|---|---|
| Process sequence | `nanoSequenceMC` | `nanoSequence` | `nanogenSequence` + `scoutingNanoSequence` |
| Output module | `NANOAODSIMoutput` | `NANOAODoutput` | `NANOAODSIMoutput` |
| Data tier | `NANOAODSIM` | `NANOAOD` | `NANOAODSIM` |
| Event content | `NANOAODSIMEventContent` | `NANOAODEventContent` | `NANOAODSIMEventContent` |
| Mixing module | Loaded (`mixNoPU`) | Not loaded | Loaded (`mixNoPU`) |
| GenParticle info | Yes | No | Yes (via `nanogenSequence`) |

### By Year

The primary difference between years is the GlobalTag. See
`des/configs/global_tags.md` for the full mapping.

### Scouting vs Standard

The scouting config (`MC_2024_Scouting.py`) diverges significantly:
- Loads `nanogen_cff` and `custom_run3scouting_cff` instead of `nano_cff`.
- Runs two NanoAOD steps: generator info (`nanogenSequence`) and scouting
  objects (`scoutingNanoSequence`).
- Applies scouting-specific customizations: `addScoutingPFCandidate`,
  `customiseScoutingNano`, `customiseScoutingNanoFromMini`.
- Adds ScoutingTranslator via `addAll()` for AK4/AK8 jet reclustering with
  UParT and HLT ParticleNet taggers.
- Explicitly keeps `edmTriggerResults` in the output.
